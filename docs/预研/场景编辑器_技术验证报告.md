# 场景编辑器技术验证报告：OpenDRIVE + OpenSCENARIO 导入、渲染与导出

> 前置文档：`场景编辑器_OpenDRIVE与按帧编辑_技术预研.md`
> 验证日期：2026-11-11
> 结论：**可行。** 在浏览器里用纯 TypeScript 解析 .xodr / .xosc、计算车道几何、渲染路网和目标物、无损导出，这几条路都走通了，并经 esmini 交叉验证。

## 1. 验证目标与选型

| 目标 | 判定标准 |
| --- | --- |
| 解析任意 xodr 并画出车道 | 车道边界与 esmini 计算结果的偏差 < 5 cm |
| 解析 xosc，算出目标物初始位置 | 与 esmini 仿真第 0 帧的位置偏差 < 5 cm |
| 导入后原样导出 | esmini 读取导出文件的结果与原文件**完全一致** |
| 大地图可流畅浏览 | 解析 + 采样耗时、缩放拖拽的流畅度 |

本次选型（已确认）：XML 用浏览器 `DOMParser`；渲染用 Konva / react-konva（`konva@10.9.1`、`react-konva@19.3.2`）；用 esmini v3.10.2 回读校验；样例使用 esmini 官方的 16 份 xodr 与 43 份 xosc。

## 2. 实现内容

代码位于 `src/features/scene-editor/`，核心模块与 React 无关：

```
core/
  xml.ts                  DOMParser 解析与序列化，保留完整 DOM
  opendrive/
    types.ts / parse.ts   路网模型：道路、几何、车道段、车道、标线、路口、通行规则
    geometry.ts           五种平面几何求值（line / arc / spiral / poly3 / paramPoly3）
    lanes.ts              laneOffset + 宽度/边界多项式 → 车道横向范围；采样成多边形；车道/道路坐标 → 世界坐标
  openscenario/
    expression.ts         参数引用 $name 与 ${…} 算术表达式（递归下降，不用 eval）
    parse.ts / types.ts   实体、初始位置、初始速度、折线轨迹；参数作用域逐层继承
    resolve.ts            七种位置类型解析为世界坐标，相对位置按依赖顺序迭代
  __verify__/             与 esmini 的交叉验证（需 ESMINI_HOME，否则跳过）
hooks/use-scene-document.ts   导入、解析、计时、导出
components/SceneCanvas.tsx    Konva 画布：车道、标线、实体、轨迹；拖拽平移、滚轮缩放、悬停识别车道
components/SceneInspector.tsx 信息面板：统计、实体列表、未支持内容提示
```

验证页面：`/scene-editor/:sceneId`。可以导入本地文件；开发环境也支持 `?xodr=URL&xosc=URL` 直接加载，xosc 引用的 LogicFile 会按相对路径自动加载。

**导出为什么能无损**：解析时保留整棵 DOM，模型只读；导出时直接序列化 DOM，未识别的节点、属性、注释都不会丢。后续做编辑时，只改用户动过的节点。

## 3. 验证结果

### 3.1 OpenDRIVE：16 / 16 通过

做法：用 esmini 的 `odrplot` 导出每条车道的边界采样点，逐点计算到我方折线的最短距离。

| 指标 | 结果 |
| --- | --- |
| 车道几何最大偏差 | **1.4 mm**（soderleden.xodr，paramPoly3）；其余 15 份 ≤ 0.1 mm |
| 覆盖的几何类型 | line、arc、spiral、paramPoly3（poly3 只有单元测试覆盖，样例中没有） |
| 覆盖的车道特性 | 多车道段、laneOffset、宽度多项式、路口连接道路、左侧通行（LHT） |
| 原样导出后 esmini 读取结果 | 16 份全部与原文件逐字节一致 |

### 3.2 OpenSCENARIO：43 / 43 通过

做法：用 esmini 无界面仿真并记录 CSV。①取第 0 帧各实体位姿，与我方解析结果对比；②分别仿真原文件和导出文件，比较整段轨迹。

| 指标 | 结果 |
| --- | --- |
| 初始位置 | 可运行的 42 份中，40 份已解析实体的偏差 ≤ 1.5 mm、朝向一致；另 2 份差异来自 esmini 特有行为（见下）。13 份含未解析实体（见下表） |
| 已支持的位置类型 | World、Lane、Road、RelativeObject、RelativeWorld、RelativeLane、RelativeRoad，含 Orientation 的 absolute / relative |
| 导出后整段仿真轨迹 | 37 份确定性场景**全部一致**；5 份 esmini 自身每次运行结果不同（随机交通流、SUMO 联合仿真），不做比对；1 份需要参数分布文件，无法单独运行 |

验证过程中定位并修复的问题：

- `Orientation type="relative"` 应叠加在**车道行驶方向**上，而不是参考线方向。
- `RelativeRoadPosition.dt` 相对于参考实体的 t，而不是相对于参考线。
- 左侧通行道路（`rule="LHT"`）的车道行驶方向相反。
- `RelativeLanePosition` 的 ds 方向和默认朝向，要跟随参考实体的**实际朝向**（实体可以逆着车道放置）。
- **浏览器导出产生双重 XML 声明**：Chrome 的 `XMLSerializer` 会自己输出 `<?xml … standalone?>`，jsdom 不会，所以单元测试和 esmini 测试都没发现，是在浏览器实测时发现的。已修复，并补了针对该行为的单元测试。

未解析或有差异的实体（不影响结论，均为验证范围外）：

| 情况 | 涉及样例 | 原因 / 后续 |
| --- | --- | --- |
| RoutePosition | ltap-od、synch_with_steady_state、pedestrian 等 7 处 | 需要解析 Route（含目录中的 Route）并沿路线定位，正式版实现 |
| 运行时生成的实体 | `Ego_ghost`、`Truck+` 等 | esmini 按控制器 / 挂车自动生成，场景文件里没有这些实体 |
| 挂车位置 | trailers.xosc | 由牵引连接决定，需要实现 TrailerAction |
| esmini 特有对齐 | drop-bike.xosc 的自行车 | esmini 额外做了 1.2 m 纵向对齐，规范中没有对应描述 |

### 3.3 浏览器实测

| 场景 | 结果 |
| --- | --- |
| multi_intersections.xodr（500 KB，63 条道路，5 个路口，242 个车道片） | 解析 18–58 ms，采样 35–152 ms（首次加载含 JIT 预热）；缩放、拖拽、悬停识别流畅 |
| cut-in.xosc | 自动加载引用的 e6mini.xodr，车辆位置、虚线标线正确 |
| trajectory-test.xosc | 折线轨迹正确显示；Clothoid / Nurbs 轨迹在"未支持的内容"中列出 |
| 导出 | 浏览器中导出的文件只有一个声明，重新解析无错误，DOM 与原文件一致 |
| 包体积 | 场景编辑器路由代码块 358 KB（gzip 后 111 KB），按路由懒加载，不影响其他页面 |


## 4. 结论与风险更新

**结论**：技术路线可行，原预研中"路网核心最需要测试保障"的判断得到验证。用 esmini 做基准的交叉验证方法很有效，第 2 节修复的 5 个问题都是靠它或浏览器实测发现的，单靠阅读规范很难发现。

| 预研时的风险 | 现在的判断 |
| --- | --- |
| 导入任意 xodr 后能否正确显示 | **已消除**：16 份官方样例毫米级一致 |
| 导出是否会丢内容 | **已消除**：保留 DOM 的方案在 53 份文件上验证无损 |
| 大地图性能 | **基本消除**：500 KB 地图流畅；更大地图（城市级，数 MB）尚未测试 |
| 路口几何编辑（改道路形状时重新生成连接道路） | **仍是最大风险**，本次未涉及 |
| OpenSCENARIO 规模 | 可控：可视化编辑只覆盖实体、位置、轨迹、速度，其余内容原样保留已验证可行 |

**尚未覆盖**：高程与超高（只做平面）、`geoReference` 投影、OpenDRIVE 1.8 的 junction boundary（路口内车道之间的空隙目前露出背景）、xosc 目录文件加载（实体尺寸暂用默认值）、RoutePosition、Clothoid / Nurbs 轨迹。

## 5. 下一步建议

1. **第 1 阶段（查看与回放）**：加载目录文件得到真实尺寸，补 RoutePosition，加时间轴、按关键帧回放轨迹，补路口面填充。
2. **第 2 阶段（编辑动态目标物）**：在 DOM 上写回实体与轨迹的修改，每次导出都跑 esmini 回读。
3. 在第 3b 阶段（路网几何编辑）之前，单独做一次"拖动道路形状 + 重新生成路口连接道路"的技术验证。

需要确认：下游消费方及版本（决定坐标系、版本取舍）；是否需要用你们自己的地图再做一轮验证。

```bash
pnpm vitest run src/features/scene-editor

```
